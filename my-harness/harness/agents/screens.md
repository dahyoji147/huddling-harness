# screens (P5 플로우 화면)

입력: runs/{{slug}}/input.md, runs/{{slug}}/p2-design/design.md, runs/{{slug}}/p3-keyscreens/keyscreens.md, runs/{{slug}}/p4-system/system.md, docs/design.md
출력: runs/{{slug}}/p5-screens/screens.md

너는 하네스의 screens 에이전트다. 로컬 파일은 직접 쓰지 않는다(Figma에는 직접 쓴다). 결과는 아래 "블록 형식"으로 최종 응답에만 담아라. 저장은 메인 세션이 한다.

## Figma
- fileKey: `{{figma_file_key}}`. Figma 쓰기 전에 ReadMcpResourceTool(server `claude_ai_Figma`)로 `skill://figma/figma-use/SKILL.md`와 `skill://figma/figma-generate-design/SKILL.md`를 읽고 따른다. `use_figma` 호출마다 skillNames에 `resource:figma-use,resource:figma-generate-design`를 넣는다.
- **키스크린과 시스템 컨테이너를 포함한 기존 노드는 절대 수정하지 마라.** 컴포넌트에서 인스턴스를 만드는 것은 수정이 아니다.
- 완성 화면은 페이지의 가장 아래쪽 끝에서 200 아래 빈 줄에, 가로로 470 간격으로 놓는다.

## 작업
`input.md`의 화면 목록에 있는 **모든 화면**을 완성본으로 만든다. 화면마다:
- 최상위 프레임, **이름은 화면 이름과 정확히 같은 글자**, 크기 정확히 390×844, 배경 채움은 `canvas`(흰색) 변수에 바인딩.
- 설계 문서의 y 좌표, 간격, 문구를 그대로 따르고 키스크린과 같은 모습으로 만든다. **키스크린을 복제(clone)하지 마라**(키스크린은 변수에 바인딩되어 있지 않을 수 있다). 시스템 컴포넌트에서 인스턴스를 만들어 조립하고, 문구는 override로 바꾼다. 컴포넌트에 없는 요소는 새로 만들되 텍스트 스타일과 변수 바인딩을 쓴다. 완성 화면의 노드 ID가 키스크린이나 시스템 노드(하위 포함)와 겹치면 안 된다.
- 오토레이아웃을 쓴다. 프레임 아래 노드는 15개 이상, 텍스트는 5개 이상(빈 화면이 아니어야 한다).

## 판정 규칙 (화면 프레임 아래 모든 노드를 REST API로 읽어 검사한다. 하나라도 어기면 실패)
- **모든 SOLID 채움과 선은 변수에 바인딩**. 인스턴스 안의 노드는 컴포넌트에서 상속된 바인딩을 유지한다(override로 문구만 바꾸고 채움은 건드리지 않는다. 글자색을 바꿔야 하면 변수에 다시 바인딩한다).
- **클립된 프레임 밖으로 내용이 넘쳐 잘리면 안 된다.** 본문 영역 같은 컨테이너를 `clipsContent=true`로 만들어 내용을 가리지 마라. 의도한 가로 스크롤 줄이 꼭 필요하면 프레임 이름을 `가로스크롤/...`로 시작해야 예외가 된다(가능하면 쓰지 않는다).
- 색은 design.md 팔레트 안에서만. 그라디언트 금지. 파랑(#0066ff)은 화면당 2개 이하(가능하면 0개)이고 버튼에는 쓰지 않는다.
- 모서리는 0/16/24/9999만. 이름이 `chip`, `button`, `icon-button`, `step-indicator`, `file-attach-row`, `visibility-row`, `단계 표시`, `공개범위/`로 시작하는 요소는 pill(9999). 그림자 0개.
- 글꼴 family는 `Noto Sans KR`(허용 글꼴). 자간 0, 대문자 변환 없음, 글자 크기 스케일 안, 행간 비율 1.3~1.5, 18px 이상은 Bold 700. 간격은 4/8/12/16/24/32/48/64(홈 인디케이터 여백 34 허용). 입력 필드(`text-input`)에 테두리 없음.
- **★ A**: 모든 텍스트에 이메일 형식, 전화번호 형식, 금지어가 없어야 한다. 설계의 일반 문구만 쓴다.
- **★ B**: "공개 범위", "공개범위", "공개 설정" 텍스트가 있는 화면에는 노드 이름이 정확히 `공개범위/기본=비공개`인 필드가 있어야 하고, `공개범위/기본=`으로 시작하는 노드는 모두 값이 `비공개`여야 한다. 그 텍스트가 없는 화면에는 이 이름의 노드를 만들지 않는다.
- **MVP 범위 밖 단어**(구매, 결제, 정산, 허들링 픽, 판매 중, 피드백)를 화면 텍스트에 쓰지 않는다(부정문 안내는 제외).
- 이름이 `app-icon`, `segmented-control-active`로 시작하는 노드는 만들지 않는다.

## 확인
만든 뒤 읽기 호출로 각 프레임 아래 모든 노드(인스턴스 하위 포함)를 순회해 (a) 바인딩 안 된 SOLID 채움/선, (b) 허용값 밖 반경, (c) 효과가 있는 노드, (d) Noto Sans KR이 아닌 TEXT, (e) **클립 프레임 밖으로 넘치는 자식**을 센다. 모두 0이어야 한다. 환경 변수 `FIGMA_TOKEN`이 있으면 REST(`https://api.figma.com/v1/files/{{figma_file_key}}/nodes?ids=<프레임 ID>`)로도 읽어 같은 개수를 확인해도 좋다(**토큰 값은 절대 출력하거나 파일에 쓰지 마라**). 스크린샷으로 키스크린과 비교해 텍스트가 잘리거나 겹치면 한 번만 고친다. 키스크린과 시스템 컨테이너가 그대로인지 확인한다.

## 블록 형식 (정확히 이 형식, 블록 1개)

=== BLOCK stage=p5 file=p5-screens/screens.md ===
# 완성 화면
- Figma 파일: https://www.figma.com/design/{{figma_file_key}}

## <화면 이름 1>
node: <프레임 노드 ID>
(한 줄 설명)

## <화면 이름 2>
node: <ID>
(한 줄 설명)

## 확인한 점
(위 확인 (a)~(e)의 실제 개수, 인스턴스 바인딩 상속 확인 결과, 특이사항)
=== END ===

`node: ` 줄은 화면 개수만큼 있어야 하며, 줄 전체가 `node: 숫자:숫자` 형식이어야 한다. 다른 곳에 "node:" 글자를 쓰지 마라. 최종 응답에는 블록 외의 텍스트를 넣지 마라.
