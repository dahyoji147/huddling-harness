# 에이전트 템플릿

오케스트레이터(메인 세션)는 단계마다 이 폴더의 템플릿을 읽고 `{{slug}}`, `{{figma_file_key}}`를 채워 에이전트를 호출한다. 지시문을 대화에서 새로 쓰지 않는다.

| 단계 | 템플릿 | 하는 일 |
|---|---|---|
| P1 | `researcher.md` | 레퍼런스 수집, 반영 포인트 선별 |
| P2 | `designer.md` | 화면 설계 |
| P3 | `keyscreen.md` | 키스크린 2~3장을 Figma에 제작 |
| P4 | `system.md` | 토큰 변수, 텍스트 스타일, 컴포넌트를 Figma에 제작 |
| P5 | `screens.md` | 화면 목록의 모든 화면을 Figma에 제작 |

## 공통 약속
- 에이전트는 로컬 파일을 직접 쓰지 않는다. 결과를 `=== BLOCK stage=pN file=<단계 폴더>/<파일> ===` ... `=== END ===` 블록으로 최종 응답에만 담는다. 메인 세션이 태그가 가리키는 단계 폴더에만 가공 없이 저장한다.
- Figma 쓰기는 에이전트가 직접 하고, 노드 ID는 블록의 `node: 숫자:숫자` 줄(줄 전체가 그 형식)로 돌려준다.
- 판정은 judge 스크립트만 한다. 에이전트의 "통과했다"는 말은 믿지 않는다.
- 템플릿의 `입력:` 줄은 에이전트가 읽을 파일 목록이다. 경로를 바꾸면 `harness/tests/docs-paths.test.mjs`가 실패하므로 템플릿도 같이 고친다.
- 템플릿 자체는 해시 고정 대상이 아니지만, `harness/` 아래라서 훅(`guard.mjs`)이 편집 전에 사람 확인을 요구한다.

## 플레이스홀더
- `{{slug}}`: run 이름 (영문 소문자와 하이픈)
- `{{figma_file_key}}`: `CLAUDE.md`의 기본 Figma 파일 키 또는 run의 `state.json`에 적힌 값
