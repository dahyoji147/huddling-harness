# 게이트 (R5)

기계가 셀 수 있는 조건은 `harness/rules.yaml`에 둔다. 이 문서는 그 요약이다.

## 게이트 목록

| 게이트 | 위치 | 통과 조건 (기계가 셈) | 실패 시 |
|---|---|---|---|
| G1 | P1 → P2 | 반영 포인트 5개 이상, 포인트마다 출처 URL 1개 이상 | P1 재시도 |
| G2 | P2 → P3 | 화면 목록의 모든 화면이 `design.md`에 정보 구조를 가짐 (누락 0건) | P2 재시도 |
| G3 | P3 → 컨펌 | 키스크린 2~3개이고 모두 390×844 | P3 재시도 |
| 👤 컨펌 | P3 → P4 | 사람이 `confirm/confirm.md`에 `approved` 기록 | 반려 시 P2 |
| G4 | P4 → P5 | 반경이 0/16/24/9999 밖인 것 0건, 그림자 0건, 허용 글꼴(Pretendard, 임시로 Noto Sans KR) 외 글꼴 0건, `design.md` 토큰에서 만든 Figma 변수에 바인딩되지 않은 채움·글자색 0건 | P4 재시도 |
| G5 | P5 → 끝 | 모든 화면 390×844, 화면이 비어 있지 않음(FRAME, 노드 15개 이상, 텍스트 5개 이상), 화면 노드가 키스크린·시스템 노드와 겹치지 않음, 클립된 프레임 밖으로 내용이 넘쳐 잘리는 곳 0건(의도한 가로 스크롤은 이름이 `가로스크롤`로 시작하면 예외), `#0066ff`(채움·선) 화면당 2개 이하, ★ A·B 위반 0건, 컨펌 승인과 G4 시스템 지문이 그대로 | 승인된 키스크린이 바뀌었으면 컨펌, 시스템 노드가 바뀌었거나 시스템 파일이 없으면 P4, 그 외 화면 위반은 P5 |

## ★ 게이트 (`story-service.md`의 "어기면 안 되는 것")

- **★ A (민감정보)**: 화면의 모든 텍스트에서 이메일 형식, 전화번호 형식이 0건. 고객사명 금지어 목록은 처음엔 비워 두고 `rules.yaml`에 쓰면서 추가한다.
- **★ B (공개 범위 기본값)**: "공개 범위" 필드가 있는 모든 화면에서 기본 선택값이 `비공개`가 아니면 위반 1건. 위반 0건이어야 G5를 통과한다. 필드 노드 이름은 `공개범위/기본=비공개`처럼 쓰는 규칙을 따른다.

## 실패 한도

- 같은 게이트에서 3회 실패하면 차단하고 사람에게 보고한다.
- 이 규칙이 `pipeline.md`의 "복귀 지점마다 최대 2회"를 대체한다.

## 지문 대조

에이전트가 쓴 단계 파일을 믿지 않고, 판정자가 Figma의 실제 상태를 읽어 대조한다.

| 단계 | 내용 |
|---|---|
| 기록 | 단계가 끝나면 스크립트가 Figma 노드 트리(노드 ID, 이름, 크기, 반경, 그림자, 색, 글꼴, 텍스트)를 해시한 지문을 `state.json`에 적는다 |
| 대조 | 판정자가 게이트 직전에 같은 노드를 다시 읽어 지문을 계산하고 `state.json`과 비교한다 |
| 불일치 | 단계 파일과 실제 상태가 다르므로 게이트 실패로 처리하고 실패 횟수에 포함한다 |
| 컨펌 | `confirm.md`에 `slug`와 컨펌 시점의 키스크린 지문을 같이 기록한다. P4 시작 때 지문이 다르면 승인을 무효로 처리하고 컨펌을 다시 받는다. 다른 run의 승인은 재사용할 수 없다 |

## 판정자 입력과 고정

- judge는 에이전트가 만든 export, JSON, 스크린샷을 입력으로 받지 않는다. Figma에서 직접 읽은 값만 판정에 쓴다.
- judge 스크립트의 해시를 `harness/rules.yaml`에 적고, 실행 때 일치하지 않으면 종료 코드 3(차단)으로 끝낸다.
- 해시 대상은 `judge.mjs`, `state.mjs`, `pin.mjs`, `lib/*.mjs`, 그리고 해시 줄을 뺀 `rules.yaml`이다. 기준(허용 반경, `failure_limit` 등)을 바꾸면 해시가 달라진다.
- 해시 갱신(`pin.mjs`)과 컨펌 기록(`state.mjs confirm`)은 `HARNESS_HUMAN=1`일 때만 실행된다. 오케스트레이터는 사람의 트리거가 있을 때만 이 값을 붙인다.
- 한계: 파일 쓰기 권한이 있는 쪽이 `pin.mjs`까지 실행하면 해시를 다시 맞출 수 있다. 에이전트가 `harness/`를 편집하지 못하게 하는 것은 권한 설정으로 막아야 한다.

## 가이드(`design.md`) 규칙과 스크립트 검사 대응

`docs/design.md`의 Do's and Don'ts 중 스크립트로 셀 수 있는 규칙은 모두 `harness/rules.yaml`의 `design`, `guide`, `star_a`, `star_b`, `scope`에 있고 G4(시스템 노드), G5(화면 노드)가 검사한다.

| 가이드 규칙 | 검사 (규칙 이름) | 상태 |
|---|---|---|
| 캔버스는 흰색 | 화면 배경이 `#ffffff`가 아니면 `screen_not_canvas` | 검사함 |
| 모든 인터랙션 요소는 pill | 이름이 `chip`, `button` 등으로 시작하는 요소는 반경 9999, 아니면 `not_pill` | 검사함 |
| 그림자 없음 | `shadow` | 검사함 |
| 모서리는 0/16/24/9999 | `radius` | 검사함 |
| 파랑은 상업 신호만, CTA 금지 | 화면당 개수 `accent_count`, 버튼에 쓰면 `accent_on_cta` | 검사함 |
| 추가 색조, 그라디언트 금지 | 팔레트 밖 색 `color_off_palette`, `gradient_fill` | 검사함 |
| 입력 필드는 쉴 때 테두리 없음 | `input_border` | 검사함 |
| 자간 0, 대문자 변환 금지 | `letter_spacing`, `text_case` | 검사함 |
| 제목은 Bold 700, 행간 1.3~1.35, 본문 1.5 | `heading_weight`, `line_height`, 크기는 `font_size_off_scale` | 검사함 |
| 간격은 8px 기준 토큰 | `spacing_off_scale` (34는 홈 인디케이터 여백으로 허용) | 검사함 |
| 글꼴 | `font` (Pretendard, 임시로 Noto Sans KR) | 검사함 |
| 색은 변수 토큰 | `color_unbound` | 검사함 |
| MVP 범위 밖 항목(구매, 결제, 정산, 허들링 픽, 판매 중, 피드백) 없음 | `mvp_out_of_scope` | 검사함 |
| ★ A 민감정보, ★ B 공개 범위 기본값 | `star_a_*`, `star_b_*` | 검사함 |
| 잘림 없음 | `content_clipped` | 검사함 |
| 대비 30% 스퀴클 아이콘, 흑백 인물 사진, 푸터 반전, 30% 반경 | 이번 화면에 해당 없음 | 검사 안 함 (해당 화면이 생기면 추가) |
| 제목은 300 굵기 부제와 짝 | 문서상 권장 사항이라 기계 검사 안 함 | 검사 안 함 |

- 금지어 검사(`star_a_word`, `mvp_out_of_scope`)는 부정문("넣지 말아 주세요", "지원하지 않아요")을 제외한다(`negation_regex`). 이메일·전화번호 형식은 문장과 관계없이 잡는다.

## 빈 입력과 입력 불량

- 검사할 대상이 비어 있으면 통과가 아니라 실패다: 화면 목록 없음(`screen_list_empty`), 노드 없음(`no_nodes`), 단계 파일이나 노드를 찾을 수 없음(`input_invalid`).
- 노드 ID는 `node: 1:2` 형식만 받는다.
- 이런 입력 불량도 게이트 실패 횟수(3회)에 들어가고 `verdict.json`에 남는다. `verdict.json`의 `status`로 실패(`fail`), 대기(`wait`), 반려(`rejected`), 차단(`blocked`)을 구분한다.

## 지문 확인 시점

- G4, G5: `confirm.md`가 이 run의 `approved` 기록(slug 일치)이고 컨펌 때 기록한 키스크린 지문과 현재 키스크린이 같아야 한다. 다르거나, 기록이 없거나, 다른 run의 기록이거나, 키스크린 노드가 Figma에서 사라졌으면 `approved_keyscreens_changed`로 컨펌 단계로 돌아간다. 이 경우는 게이트 실패 횟수가 아니라 `reconfirm` 횟수로 세고, 3회에 닿으면 차단하고 사람에게 알린다.
- G5: G4 통과 때 기록한 시스템 지문과 현재 시스템 노드가 다르면 `fingerprint_changed`로 실패하고 P4로 돌아간다.
- 지문 대상 속성: 이름, 종류, 크기, 최상위 노드 기준 상대 위치(프레임 전체를 캔버스에서 옮기는 것은 변경으로 보지 않음), 반경, 채움(그라디언트, 이미지 포함), 선(굵기, 정렬), 그림자(종류, 반경, 색), 표시 여부, 투명도, 변수 바인딩, 오토레이아웃 간격, 글꼴(종류, 굵기, 크기), 텍스트와 글자 구간 덮어쓰기.
- 되돌아갈 때는 그 단계 이후의 완료 기록과 지문을 지운다.

## 저장과 컨펌 기록

- `state.json`과 단계 파일은 임시 파일에 쓴 뒤 이름을 바꿔 저장한다. 도중에 죽어도 반쯤 쓰인 파일이 남지 않는다.
- `state.mjs confirm`은 사람 표시(`HARNESS_HUMAN=1`)에 더해 judge 해시와 입력 파일 해시가 맞을 때만 기록한다. 반려 사유는 공백뿐이면 거부한다.
- 테스트용 `--fixture`와 `HARNESS_RUNS_DIR`는 `HARNESS_TEST=1`이고 run 폴더가 임시 폴더 안일 때만 쓸 수 있다. 실제 run은 Figma 실제 응답으로만 판정한다.
- `verdict.json`에는 판정한 단계(`stage`)와 판정 뒤 단계(`next_stage`)를 따로 기록한다.
