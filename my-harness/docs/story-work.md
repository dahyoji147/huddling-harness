# 작업 흐름 (R1-B)

AI 없이 손으로 했던 실제 순서. 주어는 "디자이너(나)"로 가정한다.

## 작업 문장

| # | 문장 | 표시 |
|---|---|---|
| 1 | 디자이너가 레퍼런스를 수집한다. | |
| 2 | 디자이너가 레퍼런스에서 반영할 포인트를 고른다. | 멈칫 (반영 판단) |
| 3 | 디자이너가 반영 포인트로 화면을 설계한다. | |
| 4 | 디자이너가 키스크린 2~3개를 만든다. | |
| 5 | 팀이 키스크린을 내부 컨펌한다. | 멈칫 (내부 컨펌), 넘김 (팀에게) |
| 6 | 디자이너가 토큰, 컴포넌트, 나머지 화면을 만든다. | |
| 7 | 디자이너가 결과물이 `design.md` 가이드를 위반하는지 검토한다. | 멈칫 (`design.md` 준수) |

## 추출 결과

**명사 (산출물 후보)**
- 레퍼런스 모음
- 반영 포인트 목록
- 화면 설계 (정보 구조와 플로우)
- 키스크린 2~3개
- 컨펌 결과
- 토큰, 컴포넌트, 화면 (최종 세트)
- 가이드 위반 검토 결과

**멈칫 (게이트 위치 후보)**
- G1: 2→3 사이, 반영 판단
- G2: 5, 내부 컨펌 (사람 승인 지점 후보)
- G3: 6→끝 사이, `design.md` 준수 (기계 판정 후보)

**넘김 (에이전트 경계 후보)**
- 5번 내부 컨펌만 사람(팀)에게 넘긴다.
- 그 외 넘김은 없다. 에이전트 경계는 R3, R6에서 정한다.

## 가정

- 레퍼런스 수집 도구: uibowl (앱 UI 레퍼런스 DB)
- `story-service.md`의 "어기면 안 되는 것"은 이 문서의 재료가 아니라 R5 게이트의 판정 기준으로 쓴다.
